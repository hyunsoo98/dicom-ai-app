# DICOM AI App — 프로젝트 계획서

개인 포트폴리오 프로젝트. 의료영상(X-ray) 노이즈 저감 모델을 학습하고, ONNX/TensorRT로
최적화한 뒤, X-ray 발생장치 시뮬레이터 + DICOM 뷰어와 엮어 하나의 파이프라인으로 완성한다.

## 1. 목표

의료영상 복원/노이즈 저감, ONNX 변환·TensorRT 추론 최적화, Git/Docker 기반 개발 환경,
로컬 MLOps 자동화, 영어 기술 문서 작성 역량을 하나의 일관된 프로젝트로 보여준다.

## 2. 전체 아키텍처

```
[콘솔 앱] --TCP(자체 설계 프로토콜)--> [X-ray 소스 시뮬레이터]
                                              |
                                        CAPTURE 명령 수신
                                              v
                              kVp/mA 기반 합성 노이즈 X-ray 이미지 생성
                                              v
                          표준 DICOM(DX)으로 패키징 -> C-STORE 전송
                                              v
                              [DICOM 뷰어] 가 수신, 자동으로 열림
                                              v
                        뷰어 내 "노이즈 저감" 버튼 -> ONNX 모델로 추론
                                              v
                              원본/디노이징 결과 비교 표시
```

TensorRT 최적화(FP32/FP16/INT8 벤치마크)는 뷰어 앱과 분리된 별도 파이프라인 산출물로
다룬다 — 뷰어 자체는 배포 단순성을 위해 ONNX Runtime(CPU/DirectML)만 사용한다.

## 3. 준수 규칙 (반드시 지킬 것)

### 3-1. 제3자 IP 배제
과거에 리버스 엔지니어링(디컴파일)으로 얻은 특정 상용 장비 프로토콜/자산은 이 프로젝트에
**일체 포함하지 않는다.**

- 배제 대상: 특정 제조사명·제품명 문자열, 그 회사 실기기에서 추출한 이미지/아이콘/로고,
  리버스 엔지니어링으로 얻은 정확한 통신 프로토콜 값(커맨드 코드, 클램프 수치, 프레이밍 규칙)
- 재사용 가능한 것: "TCP로 하드웨어 상태를 흉내낸다"는 소프트웨어 아키텍처 패턴 자체
  (세션 클래스 + 커맨드 디스패치 테이블 + 상태 동기화 + 비동기 이벤트 시뮬레이션 같은 범용 설계)
- 이 프로젝트의 통신 프로토콜, 명령 코드, 파라미터 범위/클램프 로직은 전부 처음부터
  독자적으로 설계한다.

### 3-2. 퍼블리시 전 저작권·라이선스 점검
GitHub에 올리거나 공개하는 시점마다 매번 다음을 확인한다.

- 포함된 코드/데이터/에셋이 본인 저작이거나, 재사용 라이선스와 출처 표기가 명확한가
- 제3자 공개 데이터셋(예: 공개 흉부 X-ray 데이터셋)을 쓸 경우 라이선스·출처 고지를 남겼는가
- 다른 개인 프로젝트의 코드를 재사용할 경우, 그 프로젝트의 기존 라이선스를 그대로 복사하지
  않고 이 프로젝트에 맞게 라이선스 여부를 다시 판단하는가
- 회사 소속 시절 업무로 만든 자산이 섞여 있지 않은가 (전부 개인 사이드 프로젝트 결과물만 사용)

## 4. 구성 요소

| 컴포넌트 | 설명 | 기술 |
|---|---|---|
| 소스 시뮬레이터 | 가상 X-ray 발생장치. TCP 서버로 상태 관리, 자체 설계 프로토콜 사용 | Python, asyncio/socket |
| 콘솔 앱 | 노출 파라미터(kVp/mA/모드) 조작 UI | 데스크톱(Tkinter/PyQt) 또는 웹(Streamlit) 우선, 이후 확장 검토 |
| 노이즈 모델 | kVp/mA -> 광자수 추정 -> Poisson-Gaussian 노이즈 강도 매핑 | numpy |
| 디노이징 모델 학습 | 저선량 합성 노이즈 -> 정답 쌍으로 지도학습 | PyTorch, RED-CNN 계열 경량 모델 |
| ONNX 변환 | PyTorch -> ONNX, 전처리(정규화/리사이즈)까지 그래프에 포함 | torch.onnx.export |
| 검증 | ONNX 출력을 실제 추론 파이프라인과 비교 (wrapper끼리 비교 금지) | onnxruntime |
| TensorRT 벤치마크 | FP32/FP16/INT8 레이턴시·PSNR 비교 | TensorRT, trtexec |
| DICOM 뷰어 통합 | 수신한 이미지에 디노이징 버튼 추가, 원본/결과 비교 표시 | 기존 개인 DICOM 뷰어 프로젝트에 통합 |
| 자동화 | 학습 -> 변환 -> 벤치마크 -> 리포트 원커맨드 실행 | Makefile / 로컬 MLflow |
| 컨테이너화 | 시뮬레이터/콘솔 로컬 재현 환경 | Docker Compose |

## 5. 진행 순서

1. `pipeline/` 프로토콜·상태머신 설계 (자체 설계 TCP 프로토콜)
2. 노이즈 모델 (kVp/mA -> 노이즈 강도)
3. 디노이징 모델 학습
4. ONNX 변환 + 검증
5. TensorRT 최적화 + 벤치마크 리포트
6. 소스 시뮬레이터 구현 (위 아키텍처 패턴 재사용, 프로토콜은 신규)
7. 콘솔 앱
8. DICOM 뷰어 통합 (노이즈 저감 버튼, 비교 뷰)
9. Docker Compose + Makefile 자동화

## 6. 범위 밖

- 클라우드 인프라(AWS/Azure/GCP) 미사용 — 전부 로컬 환경 기준
- LLM 기반 기능 미포함 (별도 경험으로 대체)
- 임상 진단 목적 사용 금지 — 학습·연구용 명시
